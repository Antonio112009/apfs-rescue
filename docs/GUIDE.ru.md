# apfs-rescue: пошаговая инструкция

Инструкция для тех, кто не занимается восстановлением данных профессионально.
Она помогает достать файлы с диска Mac, который умирает или стоит в Mac,
который больше не включается. [English version](GUIDE.md).

## 0. Правила, которые берегут данные

1. **Никогда не работайте с умирающим диском напрямую.** Каждое чтение может
   его добить. Один раз снимите образ (шаг 1) и дальше работайте только с ним.
2. **Храните образ и сам диск**, пока не проверите копию.
3. **Не давайте ничему «чинить» образ или диск.** Если macOS предлагает
   «Инициализировать», «Исправить» или «Первую помощь», откажитесь.
   apfs-rescue в образы никогда не пишет, другие программы могут.
4. **Копируйте на другой диск**, не на тот, где лежат образы. apfs-rescue
   откажется писать на тот же диск.
5. **Сохраните файлы `.map` от ddrescue.** Только в них записано, какие места
   диска не прочитались.

## 1. Снять образы дисков

apfs-rescue читает *образы*: файлы, в которых побайтно лежит весь диск.
Лучшая программа для этого — [GNU ddrescue](https://www.gnu.org/software/ddrescue/).
Она сначала читает хорошие места, потом возвращается к плохим и записывает
**карту** (файл `.map`) того, что прочитать не удалось.

Нужен компьютер, который видит диск (например, диск из мёртвого Mac в
USB-переходнике или любой ПК, загруженный с флешки Linux), и внешний диск,
на котором свободного места больше, чем объём снимаемого диска.

В Linux (диск — `/dev/sdX`; проверьте командой `lsblk` и не ошибитесь диском):

```bash
sudo ddrescue -d -n /dev/sdX /media/backup/disk.img /media/backup/disk.map
sudo ddrescue -d -r3 /dev/sdX /media/backup/disk.img /media/backup/disk.map
```

Первая команда копирует всё, что читается легко, вторая трижды повторяет
плохие места. Обе пишут в одну карту, так что их можно прерывать и
продолжать.

**Fusion Drive** (iMac и Mac mini 2012–2019, у которых в «Об этом Mac» написано
«Fusion Drive»). Это два диска, маленький SSD и большой жёсткий диск, которые
macOS объединяет в один. Снимите **оба** диска в отдельные файлы, например
`ssd.img` + `ssd.map` и `hdd.img` + `hdd.map`. Нужны оба образа, одного мало.

Расширение файла не важно (`.img`, `.dmg`, `.bin`). apfs-rescue читает «сырые»
образы, а не сжатые образы из «Дисковой утилиты».

## 2. Скачать apfs-rescue

### Скачать готовую программу

Откройте на GitHub страницу проекта **Releases** и скачайте файл для своего
компьютера:

| Компьютер | Файл |
|---|---|
| Mac на процессоре Apple (M1 и новее) | `…-aarch64-apple-darwin.tar.gz` |
| Mac на процессоре Intel | `…-x86_64-apple-darwin.tar.gz` |
| Windows (большинство ПК) | `…-x86_64-pc-windows-msvc.zip` |
| Windows на ARM | `…-aarch64-pc-windows-msvc.zip` |
| Linux | `…-x86_64-unknown-linux-musl.tar.gz` или `…-aarch64-…` |

Распакуйте. Внутри программа `apfs-rescue` (в Windows `apfs-rescue.exe`), эта
инструкция и лицензия.

**Проверить, что файл настоящий** (по желанию). У каждого релиза есть файл
`SHA256SUMS.txt` и подписанная запись о сборке. С программой
[GitHub CLI](https://cli.github.com/):

```bash
gh attestation verify apfs-rescue-v0.1.0-aarch64-apple-darwin.tar.gz --repo Antonio112009/apfs-rescue
```

**Первый запуск на Mac.** Если релиз не подписан сертификатом Apple, macOS
скажет, что программу «не удаётся открыть». Один раз снимите пометку о
загрузке:

```bash
xattr -d com.apple.quarantine ./apfs-rescue
```

**Первый запуск в Windows.** SmartScreen может предупредить о неизвестном
издателе: нажмите «Подробнее → Выполнить в любом случае».

### Или собрать самому

Установите Rust с [rustup.rs](https://rustup.rs), затем:

```bash
git clone https://github.com/Antonio112009/apfs-rescue
cd apfs-rescue
cargo build --release
```

Программа появится в `target/release/apfs-rescue`.

### Как запускать

apfs-rescue работает в командной строке. Откройте **Терминал** (Mac:
Программы → Утилиты), **PowerShell** (Windows) или терминал (Linux), перейдите
в папку, куда распаковали программу, и запускайте её как `./apfs-rescue`
(Windows: `.\apfs-rescue.exe`). В примерах ниже замените пути к образам на
свои. Совет: перетащите файл из Finder или Проводника в окно терминала, и
туда вставится его полный путь.

`./apfs-rescue --help` покажет все команды, `./apfs-rescue copy --help` —
параметры одной команды.

## 3. Посмотреть, что внутри: `info`

```bash
./apfs-rescue info /Volumes/Backup/ssd.img /Volumes/Backup/hdd.img
```

Для обычного диска (не Fusion) укажите один образ. Пример вывода:

```
Using ddrescue map /Volumes/Backup/ssd.map for /Volumes/Backup/ssd.img
Using ddrescue map /Volumes/Backup/hdd.map for /Volumes/Backup/hdd.img
Fusion Drive    : yes
Checkpoint      : 44192259 (newest of 150 valid)
Volumes:
  0  "Macintosh HD - Data"      Data        1623754 files
  4  "Macintosh HD"             System       426897 files
  ...
Fusion SSD cache: 610512 ranges, 9.94 GB of HDD data has a copy on the SSD
Damaged areas   : 759 areas, 4.28 MB (from ddrescue map)
```

Что это значит:

- **Using ddrescue map** — карта рядом с каждым образом нашлась сама (она
  должна называться как образ, но с `.map`). Иначе укажите её:
  `--map путь/к/файлу.map`.
- **Volumes** — тома. В macOS 10.15 и новее ваши файлы лежат в
  **«Macintosh HD - Data»**, а в «Macintosh HD» только сама macOS. На старых
  Mac том один — «Macintosh HD». apfs-rescue сам выбирает том с данными;
  другой можно выбрать через `-v НОМЕР`.
- **Damaged areas** — сколько не прочиталось. Если это несколько мегабайт,
  обычно задето немного файлов.

## 4. Найти свою папку: `ls`

```bash
./apfs-rescue ls ssd.img hdd.img -p Users
```

покажет учётные записи. Потом загляните в нужную:

```bash
./apfs-rescue ls ssd.img hdd.img -p Users/ИМЯ
```

Где что обычно лежит:

| Что | Путь |
|---|---|
| Медиатека «Фото» | `Users/ИМЯ/Pictures/Медиатека Photos.photoslibrary` (или `Photos Library.photoslibrary`) |
| Старая медиатека iPhoto | `Users/ИМЯ/Pictures/Медиатека iPhoto.photolibrary` |
| Рабочий стол, Документы, Загрузки | `Users/ИМЯ/Desktop`, `Documents`, `Downloads` |
| Музыка и видео | `Users/ИМЯ/Music`, `Users/ИМЯ/Movies` |
| Почта | `Users/ИМЯ/Library/Mail` |
| Всё одного пользователя | `Users/ИМЯ` |

Папки в пути разделяются `/` на любой системе, в том числе в Windows. Путь с
пробелами берите в кавычки: `-p "Users/ИМЯ/Pictures/Медиатека Photos.photoslibrary"`.

## 5. Какие файлы повреждены: `damaged`

```bash
./apfs-rescue damaged ssd.img hdd.img -p Users/ИМЯ > damaged.tsv
```

Команда читает только служебные записи файловой системы, ничего не копирует и
работает быстро: около 20 секунд на 600 тысяч файлов. Каждая строка в
`damaged.tsv` выглядит так:

```
DAMAGED  <путь>  <размер>  <диапазоны байтов, где нули>
```

`DAMAGED` — данные файла попали в нечитаемые места. `REPAIRED` — плохие блоки
удалось взять из кэша Fusion на SSD. Файл удобно открыть в Excel или Numbers и
отсортировать.

**Поиск целых копий.** Фото часто хранятся дважды: в старой медиатеке iPhoto и
в «Фото», в папке с камеры и в экспорте. Добавьте `--find-copies`, и apfs-rescue
проверит весь диск: нет ли где-то файла с тем же содержимым, но без
повреждений. Такой файл допишется в строку как `intact copy: <путь>` — его и
копируйте:

```bash
./apfs-rescue damaged ssd.img hdd.img -p Users/ИМЯ --find-copies > damaged.tsv
./apfs-rescue copy ssd.img hdd.img -p "Users/ИМЯ/путь/к/целой/копии.jpg" -o ~/Восстановленные
```

`copy -p` принимает и отдельный файл, и папку.

Повреждённое фото обычно всё равно открывается, но с серой или битой полосой.
Видео обычно играет с коротким сбоем. Поищите вторую копию таких файлов в
другом месте: в старой медиатеке iPhoto, в телефоне, в облаке.

## 6. Скопировать: `copy`

```bash
./apfs-rescue copy ssd.img hdd.img -p Users/ИМЯ/Pictures -o /Volumes/НовыйДиск/Pictures
```

- `-p` — какую папку копировать (со всем содержимым).
- `-o` — куда класть копию. Только на другой диск, не туда, где образы.

Каждые 15 секунд программа показывает прогресс, а в конце итог:

```
Done: 636152 copied fine, 140 damaged, 0 errors, 0 already there. 1.22 TB written.
```

В папке с копией появится `_apfs-rescue-report.tsv`, по строке на каждый файл,
которому нужно внимание:

| Статус | Значение |
|---|---|
| `DAMAGED` | Скопирован, но часть байтов на диске не прочиталась, там нули. |
| `REPAIRED` | Нечитаемые блоки восстановлены из кэша Fusion на SSD. |
| `ERROR` | Не скопирован, причина в последней колонке. |
| `RENAMED` | Имя запрещено в этой системе (Windows), поэтому изменено. |
| `SKIPPED` | Уже скопирован при прошлом запуске. |
| `NOTE` | Скопирован, но атрибут или дату восстановить не удалось (подробности в последней колонке). |

**Копирование прервалось?** Запустите ту же команду ещё раз. Файлы, которые
уже скопированы целиком, будут пропущены.

Сохраняются даты изменения и (на Mac и Linux) права доступа. Если копировать
на Mac, сохраняются ещё даты создания, теги и цвета Finder, комментарии,
resource fork и другие расширенные атрибуты (`--no-xattrs` отключает
атрибуты). В Windows и Linux этим атрибутам Mac некуда записаться. Пометка
«скачано из интернета» намеренно не копируется. Всё, что восстановить не
удалось, попадает в отчёт со статусом `NOTE`.

## 7. Проверить копию

- Сравните числа: `info` показывает число файлов во всём томе, итог `copy` —
  сколько скопировано из вашей папки.
- Откройте из копии несколько фото, документов и видео.
- Прочитайте `_apfs-rescue-report.tsv`. Если всё хорошо, в нём только строка
  заголовка.

Только после этого решайте, что делать со старым диском. Образы сохраните.

## 7а. Старые версии и удалённые файлы: снимки

macOS хранит *снимки* (snapshots): «замороженные» виды диска на какой-то
момент в прошлом. Если включена Time Machine, она делает их примерно раз в час и
хранит около суток; ещё macOS делает снимки для обновлений системы.
В снимке может лежать удалённый файл или старая версия изменённого файла.

`info` показывает их в конце:

```
Snapshots of "Macintosh HD - Data" (use -s NUMBER):
    44191693  2026-11-09 20:06 UTC  com.apple.TimeMachine.2026-11-09-162407.local
```

Добавьте `-s НОМЕР` (или имя снимка) к `ls`, `copy` или `damaged`, чтобы
увидеть диск таким, каким он был тогда:

```bash
./apfs-rescue ls   ssd.img hdd.img -s 44191693 -p Users/ИМЯ/Desktop
./apfs-rescue copy ssd.img hdd.img -s 44191693 -p Users/ИМЯ/Desktop -o /Volumes/НовыйДиск/Desktop-снимок
```

Копируйте снимок в отдельную папку, чтобы он не смешался с текущими файлами.
Снимки делят данные с текущими файлами, поэтому повреждённые места задевают и
те, и другие.

## 7б. Смотреть диск в Finder: `mount`

Можно не копировать всё подряд, а показать старый диск как диск «только для
чтения» и посмотреть его в Finder: открыть фото через «Быстрый просмотр»
(пробел) и перетащить только нужное.

```bash
./apfs-rescue mount ssd.img hdd.img
./apfs-rescue mount ssd.img hdd.img -p Users/ИМЯ/Pictures        # одна папка
./apfs-rescue mount ssd.img hdd.img -s 44191693                  # снимок
```

Откроется окно Finder с этим диском. Изменить на нём ничего нельзя. Если открыть файл, задетый нечитаемыми местами, в терминале
появится предупреждение. Чтобы закончить, нажмите **Ctrl+C** в терминале или
**«Извлечь»** в Finder. `--at ПАПКА` задаёт, куда подключать (по умолчанию
`~/apfs-rescue-mounts`).

`mount` работает на macOS и Linux. В Windows используйте `copy`.

### Что для этого нужно

- **Mac:** ничего. apfs-rescue отдаёт диск через встроенную в macOS сетевую
  файловую систему (NFS), только внутри этого компьютера (127.0.0.1). Не нужны
  ни macFUSE, ни FUSE-T, ни системные расширения, ничего не надо включать в
  настройках. Когда диск готов, откроется окно Finder.
- **Linux:** пакет `fuse3` (`sudo apt install fuse3`).
- **Windows:** пока не поддерживается, используйте `copy`.

На Mac в подключённом диске видно содержимое, размеры и даты изменения. Теги
Finder и даты создания там не показываются (в NFS для них нет места) — их
сохраняет `copy`.

## 8. Медиатеки «Фото» и iPhoto

`.photoslibrary` — это папка, которую macOS показывает как один файл.

- **Чтобы открыть её в «Фото»**, скопируйте на диск Mac в формате APFS или
  Mac OS Extended, затем запустите «Фото», удерживая клавишу **Option**, и
  выберите «Другая медиатека…». «Фото» может какое-то время её обновлять.
- **В Windows или на диске exFAT** «Фото» медиатеку не откроет, но ваши
  оригинальные фото и видео лежат обычными файлами в папке `originals` (в
  старых медиатеках — `Masters`). Если нужны только они, скопируйте одну эту
  папку:

  ```bash
  ./apfs-rescue copy ssd.img hdd.img -p "Users/ИМЯ/Pictures/Медиатека Photos.photoslibrary/originals" -o D:\Photos
  ```

- Повреждённые файлы в `resources` — это превью, «Фото» создаст их заново.
  Важны повреждения в `originals` и `Masters`.

## 9. Сообщения об ошибках

| Сообщение | Что делать |
|---|---|
| `this is a Fusion container: pass both images` | Укажите оба образа: SSD и HDD. |
| `output folder … is on the same disk as …` | Выберите папку для копии на другом диске. |
| `several volumes found; choose one with -v NUMBER` | Запустите `info` и укажите номер нужного тома. |
| `volume … is encrypted` | Тома с FileVault пока не поддерживаются. |
| `volume … is a sealed system volume` | В этом томе только macOS, ваши файлы в «… - Data». |
| `… not found in path …` | Проверьте написание через `ls`, по одной папке за раз. |
| `metadata block … lies in an unreadable area` | Повреждена служебная запись папки. Остальное всё равно копируется, а папка попадёт в отчёт как `ERROR`. Для опытных: попробуйте `--xid` с более старой контрольной точкой. |
| `no APFS container found` | В образе не APFS (старые Mac используют HFS+) или это сжатый образ из «Дисковой утилиты». |

## 10. Вопросы

**Работает с двумя SSD, двумя жёсткими дисками или одним диском?** Да. Для
Fusion важно только, какой диск основной, а какой второй, и apfs-rescue
узнаёт это из самих дисков. Обычный диск Mac — это один образ.

**Можно читать диск напрямую, без образа?** Пока нет: программа читает файлы
образов. Для умирающего диска образ всё равно нужно снять сначала.

**Может ли программа испортить образы?** Нет. Она открывает их только на
чтение, и кода записи в них в ней нет.

**Диски HFS+?** Не поддерживаются: apfs-rescue читает APFS (macOS 10.13 и
новее).
